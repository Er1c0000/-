# 第二创新点后续阶段工作流适配分析

## 文档目的

本文件用于回答一个局部问题：

- 在第二创新点总阶段 `2-7` 中，哪些阶段适合做成明确工作流，哪些阶段更适合用循环式推进或检查清单推进。

本文件只讨论“工作方式”，不新增第二创新点的技术结论。

## 判断依据

- 总阶段定义见 `创新点二\plan.md`。
- 各阶段当前模板见：
  - `创新点二\正式文档\02_创新点方案\研究目标定义.md`
  - `创新点二\正式文档\02_创新点方案\方法框架设计.md`
  - `创新点二\正式文档\02_创新点方案\实验设计.md`
  - `创新点二\过程记录\实验记录\实现与初步验证.md`
  - `创新点二\正式文档\02_创新点方案\结果分析与创新点确认.md`
  - `创新点二\正式文档\03_论文写作\论文撰写.md`

## 工作流规范要求

后续如果在 `创新点二\工作流` 下新建工作流，目录组织应遵循以下规则：

1. `创新点二\工作流` 下的每一个一级目录，只代表一个独立工作流。
2. 每个工作流目录下，固定只分为两个子目录：
   - `工作流定义`
   - `运行记录`
3. `工作流定义` 用于放该工作流的规则文件、执行摘要、阶段模板、说明文档、skill 草稿等可复用定义材料。
4. `运行记录` 用于放该工作流的实际执行留痕，例如轮次目录、阶段产出文档、比较记录、临时过程材料等。
5. 不再使用“一个总过程目录下面混放定义文件和轮次文件”的组织方式。

推荐目录骨架如下：

```text
创新点二\工作流\
  某工作流名称\
    工作流定义\
    运行记录\
```

如果某个工作流需要多轮执行，则应在 `运行记录` 下继续分轮次，例如：

```text
创新点二\工作流\
  阶段1_创新点方向确认工作流\
    工作流定义\
    运行记录\
      工作流轮次1\
      工作流轮次2\
```

如果某个工作流当前只有规则分析、尚未正式运行，也仍然保留 `运行记录` 子目录，但可以暂时为空。

## 当前工作流目录示例

按当前目录，`创新点二\工作流` 下已存在两类工作流：

1. `阶段1_创新点方向确认工作流`
2. `后续阶段工作流规划`

其中：

- `阶段1_创新点方向确认工作流\工作流定义`：放阶段1相关的规范、摘要、模板和 skill 草稿。
- `阶段1_创新点方向确认工作流\运行记录`：放 `工作流轮次1`、`工作流轮次2` 和 `待定方向` 等过程留痕。
- `后续阶段工作流规划\工作流定义`：用于放后续阶段的工作流分析和规划文档。
- `后续阶段工作流规划\运行记录`：当前可为空，待后续真正执行相关规划工作流时再写入内容。

## 总体结论

后续阶段不适合全部照搬“阶段1遴选工作流”的模式。

更合适的划分是：

1. 有些阶段适合做成单次推进、输入输出清楚的明确工作流。
2. 有些阶段适合做成带回路的迭代工作流。
3. 有些阶段不适合做成一个大工作流，只适合拆成若干小工作流或检查清单。

## 分阶段判断

| 总阶段 | 适配判断 | 建议形式 | 原因 |
| --- | --- | --- | --- |
| 阶段2：研究目标定义 | 高度适合 | 线性明确工作流 | 输入、输出、边界都清楚，适合按固定顺序完成问题定义、目标、边界、差异和完成标准。 |
| 阶段3：方法框架设计 | 中度适合 | 循环式工作流 | 方法设计通常需要反复回看研究目标和边界，不适合一次写死，更适合“设计-自检-收缩”。 |
| 阶段4：实验设计 | 高度适合 | 线性明确工作流 | 场景、变量、基线、指标、有效性实验和边界实验都可以结构化展开，最适合显式流程。 |
| 阶段5：实现与初步验证 | 中度适合 | 迭代式工作流 | 本质是实现一版、记录现象、修一轮、再验证，不适合单次通过。 |
| 阶段6：结果分析与创新点确认 | 高度适合 | 线性明确工作流 | 可以按“整理结果-比较场景-判断成立条件-标记证据不足-沉淀可写结论”固定推进。 |
| 阶段7：论文撰写 | 低度适合 | 拆分式小工作流 / 检查清单 | 写作包含章节组织、图表挂接、口径控制，不适合做成一条从头到尾的刚性大流程。 |

## 最适合优先固化的工作流

建议优先把以下三套工作流明确化：

1. `阶段2：研究目标定义工作流`
2. `阶段4：实验设计工作流`
3. `阶段6：结果分析与创新点确认工作流`

原因：

- 这三阶段的输入输出最稳定；
- 结构化收益最高；
- 最容易避免写作和研究推进中的反复返工；
- 最适合形成可重复调用的固定模板。

## 适合后续补充的工作流

在上述三套之后，建议再考虑：

1. `阶段3：方法框架设计工作流`
2. `阶段5：实现-验证迭代工作流`

原因：

- 它们也能流程化；
- 但本质上都带有较强试错和回退特征；
- 因此更适合做成循环式，而不是单向线性流程。

## 不建议直接固化为单一大工作流的阶段

`阶段7：论文撰写` 不建议直接做成一个总工作流。

更合适的方式是拆成几个局部小工作流，例如：

1. 章节结构工作流
2. 图表清单与挂接工作流
3. 贡献表述不过界检查工作流
4. 与第一创新点衔接句整理工作流

这样更符合写作阶段“局部改动、多轮回看”的实际特点。

## 推荐优先级

如果后续准备继续把第二创新点推进流程工程化，建议优先级如下：

1. `阶段2：研究目标定义工作流`
2. `阶段4：实验设计工作流`
3. `阶段6：结果分析与创新点确认工作流`
4. `阶段3：方法框架设计工作流`
5. `阶段5：实现-验证迭代工作流`
6. `阶段7` 只做拆分式小工作流，不做总工作流

## 与现有工作流的关系

当前已经存在的“阶段1_创新点方向确认工作流”，本质上只覆盖：

- `阶段1：创新点方向确认` 的内部子阶段。

它并不自动覆盖总阶段 `2-7`。

因此，若后续继续完善“工作流目录”，最值得新增的是：

1. `阶段2` 的正式工作流
2. `阶段4` 的正式工作流
3. `阶段6` 的正式工作流

## 下一步建议

如果继续往下做，建议不要一次把 `2-7` 全部工作流化。

更稳妥的顺序是：

1. 先写 `阶段2：研究目标定义工作流`
2. 再写 `阶段4：实验设计工作流`
3. 然后写 `阶段6：结果分析与创新点确认工作流`

这三套先落地后，再决定是否继续补 `阶段3`、`阶段5` 和 `阶段7` 的局部流程。
