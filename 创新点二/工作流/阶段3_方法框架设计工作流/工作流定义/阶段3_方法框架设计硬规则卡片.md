# 阶段3：方法框架设计硬规则卡片

本卡片只服务于第二创新点总阶段 `阶段3：方法框架设计` 的执行，不替代长版规范。

## 1. 作用范围

- 本工作流中的“阶段3”指总阶段 `阶段3：方法框架设计`，不是 `阶段1_创新点方向确认工作流` 内部的第三阶段。
- 本工作流只负责把已确认问题和研究目标收束为稳定的方法框架。
- 本工作流不负责重新筛选方向，不负责详细实验设计，不负责结果分析与创新点成立判断。

## 2. 不可越界事项

- 严禁读取、引用或依据 `创新点二\工作流\阶段1_创新点方向确认工作流\运行记录\待定方向\待定方向汇总.md` 进行分析，除非用户明确解除限制。
- 严禁读取、引用或依据 `创新点二\工作流\阶段1_创新点方向确认工作流\运行记录\工作流轮次1` 目录下任何文档进行分析，除非用户明确解除限制。
- 不要把未完成的第二创新点写成既成方法、已验证效果或最终贡献结论。
- 不要把方法框架设计写成某个近年算法的局部修补说明。

## 3. 阶段3专属约束

- 默认以上游正式材料为主，优先使用 `创新点二\正式文档\02_创新点方案\研究目标定义.md` 作为稳定输入。
- 方法框架必须同时写清“哪些模块承接小论文已有结果”和“哪些模块构成第二创新点新增部分”。
- 本阶段优先形成“最小但完整”的方法模块划分，不追求一次写满所有实现细节。
- 本阶段必须写清模块输入输出、关键接口、默认假设和主要技术难点。
- 本阶段允许保留未决问题，但应明确标注，不得伪装成已确定结论。

## 4. 文献与证据约束

- 若需要论证“与现有方法差异”“某类结构仍有研究意义”或“某个模块设置具有必要性”，必须使用真实文献支撑。
- 文献支撑应优先服务于问题重要性、方法差异和研究边界说明，不用于提前为未验证方案背书。
- 不能虚构论文结论、研究进展、数据、图表信息或实验结果。

## 5. 执行约束

- 修改 `方法框架设计.md` 前，必须先读取其最新版本。
- 一次只处理一个局部问题；本工作流的局部问题是“形成稳定的阶段3方法框架口径”。
- 若发现研究目标、研究边界或与第一创新点接口仍不明确，应先停下并向用户确认。
- 若发现文本已经进入实验设计、结果分析或贡献确认层，应收回到方法框架层。

## 6. 本轮执行前自检

- 当前任务是否仍属于总阶段 `阶段3：方法框架设计`。
- 当前输出是否已经把未验证方法效果写成确定结果。
- 当前表述是否已经越过方法框架，提前进入实验设计或结果分析层。
- 当前是否区分了“承接模块”和“新增模块”。
- 当前操作是否触碰受限文件或受限目录。
